## 一、技术栈总览

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **前端框架** | Next.js 14+ (App Router) | React SSR/CSR，文件路由 |
| **UI框架** | React 18+ | 组件化开发 |
| **语言** | TypeScript 5+ | 类型安全 |
| **样式** | Tailwind CSS 3+ | 原子化CSS，快速UI开发 |
| **状态管理** | **Zustand 4+** | 轻量级状态管理，支持持久化中间件 |
| **动画** | Framer Motion + Lottie | 页面过渡+教学动画 |
| **本地存储** | Dexie.js (IndexedDB) | 离线优先，学习档案持久化 |
| **云端备份** | 自建 API (Node.js) | 数据同步与备份 |
| **TTS** | Edge TTS / Azure TTS + **Howler.js** | 温柔女声，Howler.js解决Safari AudioContext兼容性 |
| **ASR** | **Whisper API（主）** / Web Speech API（备） | Whisper为主解决Safari兼容性，Web Speech API为免费降级方案 |
| **LLM** | 多供应商适配层 | DeepSeek / Gemini / OpenAI |
| **状态机** | **XState 5+** | SessionController有限状态机，支持持久化和恢复 |
| **部署** | 自有服务器 (Docker + Nginx) | 前端SSR + API服务 |
| **CI/CD** | **GitHub Actions** | 自动化构建/测试/部署 |
| **监控** | **Sentry + Prometheus + Grafana** | 前端错误+性能+API监控 |
| **包管理** | pnpm | 快速、节省磁盘 |

### 2.2 三层核心架构

```
Layer 1: 通用教学引擎 (Subject-Agnostic)
├── SessionController     — 控制教学会话流程（基于XState有限状态机，支持持久化恢复）
├── RuleEngine            — 规则判定（掌握率、补救次数、进度）
├── AdaptiveRouter        — 自适应路径选择
├── MasteryCalculator     — 掌握率计算（累计评估，75%软门控）
├── RemediationManager    — 补救教学管理（穿插式，非阻塞）
├── ReviewScheduler       — 艾宾浩斯复习调度器
├── RewardEngine          — 激励系统（星星/等级，简化版）
└── PlacementEngine       — 入学自适应测评引擎（CAT算法）

Layer 2: 学科数据包 (Pluggable SubjectPacks)
├── english/              — 英语学科包
│   ├── knowledge-graph.json
│   ├── placement-tests.json
│   ├── teaching-methods/
│   └── assessments/
├── math/                 — 数学学科包（后续）
└── ...

Layer 3: 服务/工具层 (Replaceable Services)
├── LLMAdapter            — 统一LLM接口（多供应商）
├── TTSService            — 文字转语音
├── ASRService            — 语音识别
├── StorageService        — 数据持久化
├── ReviewPipeline        — Multi-Agent审核管线
└── MediaService          — 图片/动画/视频资源
```

## 四、核心数据模型（TypeScript类型定义）

### 4.1 学科数据包

```typescript
// ===== 学科包 =====
interface SubjectPack {
  id: string;                         // 如 "english"
  name: string;                       // 如 "英语"
  version: string;                    // 如 "1.0.0"
  targetAge: { min: number; max: number }; // { min: 4, max: 5 }
  knowledgeGraph: KnowledgeGraph;
  placementTests: PlacementTest[];
  reviewSchedule: ReviewSchedule;
  metadata: SubjectMetadata;
}

// ===== 知识图谱 =====
interface KnowledgeGraph {
  nodes: KnowledgeNode[];
  edges: KnowledgeEdge[];             // 前置依赖关系
}

interface KnowledgeNode {
  id: string;                         // 如 "en-alpha-a"
  name: string;                       // 如 "字母A认读"
  category: string;                   // 如 "alphabet"
  level: number;                      // 难度层级 1-5
  prerequisites: string[];            // 前置知识点ID
  objectives: string[];               // 学习目标
  keyConcepts: string[];              // 核心概念
  masteryThreshold: number;           // 掌握率阈值，默认0.75（软门控）
  estimatedMinutes: number;           // 预计学习时长
  teachingMethods: TeachingMethod[];  // 可用教学方式（多种）
  assessments: Assessment[];          // 评估题目
  remediationStrategies: RemediationStrategy[]; // 补救策略
}

interface KnowledgeEdge {
  from: string;                       // 前置节点ID
  to: string;                         // 后续节点ID
  type: 'prerequisite' | 'related';   // 关系类型
}
```

### 4.2 教学方法

```typescript
// ===== 教学方法 =====
interface TeachingMethod {
  id: string;
  type: 'animation' | 'video' | 'game' | 'song' | 'story' | 'interactive';
  name: string;                       // 如 "字母A动画故事"
  priority: number;                   // 优先级，补救时按序使用
  content: TeachingContent;
  duration: number;                   // 预计时长（秒）
}

interface TeachingContent {
  // 教学步骤
  steps: TeachingStep[];
  // AI老师对话脚本
  teacherScript: TeacherLine[];
  // 媒体资源
  media: MediaResource[];
}

interface TeachingStep {
  order: number;
  type: 'explain' | 'demonstrate' | 'interact' | 'practice';
  content: string;                    // 教学内容描述
  teacherSay: string;                 // AI老师说的话
  teacherSayEn?: string;              // 英文部分
  media?: MediaResource;              // 配套媒体
  interaction?: InteractionConfig;    // 互动配置
  duration: number;                   // 秒
}

interface TeacherLine {
  text: string;                       // 文字
  lang: 'zh' | 'en';                  // 语言
  emotion: 'normal' | 'excited' | 'encouraging' | 'gentle';
  timing: number;                     // 在第几秒说
}

interface MediaResource {
  type: 'image' | 'animation' | 'video' | 'lottie' | 'audio';
  url: string;
  alt: string;
}
```

### 4.3 评估与题目

```typescript
// ===== 评估 =====
interface Assessment {
  id: string;
  nodeId: string;                     // 关联知识节点
  questions: Question[];
  passingScore: number;               // 通过分数（默认75%，软门控）
  verified: boolean;                  // 是否经过审核
  verifiedAt?: Date;
  verifiedBy?: string[];              // 审核Agent列表
}
```

## 七、Multi-Agent 审核管线

### 7.1 架构设计（6个Agent角色）

```typescript
/**
 * 审核管线 - 6个Agent角色，同一个LLM不同System Prompt
 * 角色：课程设计师 + 学科专家 + 幼教专家 + 测评专家 + 安全审核 + 终审仲裁
 */
class ReviewPipeline {
  private llm: LLMAdapter;
  private agents: Map<AgentRole, ReviewAgent>;

  constructor(llm: LLMAdapter) {
    this.agents = new Map([
      ['courseDesigner', new CourseDesigner(llm)],
      ['subjectReviewer', new SubjectReviewer(llm)],
      ['childEdReviewer', new ChildEdReviewer(llm)],
      ['assessmentReviewer', new AssessmentReviewer(llm)],
      ['safetyReviewer', new SafetyReviewer(llm)],
      ['finalArbiter', new FinalArbiter(llm)],
    ]);
  }

  /**
   * 完整审核流程
   * @param content 待审核内容
   * @param level 审核力度
   * @returns 审核结果
   */
  async review(
    content: ReviewableContent,
    level: 'heavy' | 'light'
  ): Promise<ReviewResult> {
    const MAX_ROUNDS = 3;

    for (let round = 1; round <= MAX_ROUNDS; round++) {
      // Step 1: 4个审核Agent并行审核
      const reviews = await Promise.all(
        this.getReviewers(level).map(agent =>
          agent.review(content)
        )
      );

      // Step 2: 终审仲裁
      const arbiterResult = await this.agents.get('finalArbiter')!
        .arbitrate(content, reviews);

      if (arbiterResult.approved) {
        return {
          approved: true,
          content: content,
          round,
          reviews,
          arbiterResult,
        };
      }

      // Step 3: 未通过，课程设计师根据反馈修改
      content = await this.agents.get('courseDesigner')!
        .revise(content, arbiterResult.feedback);
    }

    // 3轮未过，标记需人工审核
    return {
      approved: false,
      needsHumanReview: true,
      content,
      round: MAX_ROUNDS,
    };
  }

  private getReviewers(level: 'heavy' | 'light'): ReviewAgent[] {
    if (level === 'heavy') {
      return [
        this.agents.get('subjectReviewer')!,
        this.agents.get('childEdReviewer')!,
        this.agents.get('assessmentReviewer')!,
        this.agents.get('safetyReviewer')!,
      ];
    }
    // 轻度审核只用学科专家+安全审核
    return [
      this.agents.get('subjectReviewer')!,
      this.agents.get('safetyReviewer')!,
    ];
  }
}

type AgentRole =
  | 'courseDesigner'       // 课程设计师
```

### 8.2 ASR + 发音评分

## 十二、性能优化策略

### 12.1 教学内容预加载

```
策略：在孩子学习当前模块时，后台预加载下一模块的资源

流程：
1. 开始模块N教学 → 后台加载模块N+1的图片/动画/音频
2. 开始模块N练习 → 后台预生成模块N评估的TTS语音
3. 评估达标 → 模块N+1资源已就绪，无缝切换

缓存策略：
- 图片/动画：Service Worker缓存，离线可用
- TTS音频：IndexedDB缓存，避免重复请求
- LLM响应：审核通过的内容永久缓存
```

### 12.2 LLM 调用优化

```
策略：最小化实时LLM调用，最大化预生成+缓存

- 知识图谱/题库/大纲：一次生成，审核通过后永久缓存
- 教学内容：按模块预生成，审核后缓存
- 补救策略：预生成3种备选方案缓存
- 实时互动：唯一需要实时调用LLM的场景
- 弱点诊断：每次学习结束后异步执行

预计API调用频率（每次学习25分钟）：
- 实时互动：5-10次调用
- 弱点诊断：1次调用
- 内容生成：0次（缓存命中）
- 审核管线：0次（内容已预审）
```

### 12.3 PWA 离线方案（Workbox）

```
策略：使用 Workbox 实现离线优先的 PWA 体验

Service Worker 缓存策略：
├── 静态资源（JS/CSS/图片）：Cache First（优先本地缓存）
├── 教学动画/音频：Cache First + Background Sync（后台更新）
├── API请求（LLM/TTS）：Network First + Offline Fallback
├── 学科包数据：Stale While Revalidate（返回缓存同时后台更新）
└── 预缓存：安装时预缓存核心Shell + 当前学习模块资源

离线可用能力：
├── ✅ 已缓存的教学内容（动画/图片/音效）
├── ✅ 已预生成的TTS语音
├── ✅ 本地数据读写（IndexedDB）
├── ❌ 实时LLM对话（需网络）→ 降级为预设对话脚本
├── ❌ ASR语音识别（Whisper需网络）→ 降级为点击交互
└── ❌ 云端备份（需网络）→ 本地标记，恢复网络后自动同步

Workbox配置示例：
├── workbox-precaching: 核心Shell资源预缓存
├── workbox-routing: 按资源类型匹配缓存策略
├── workbox-strategies: CacheFirst / NetworkFirst / StaleWhileRevalidate
├── workbox-background-sync: 离线操作队列，网络恢复后自动提交
└── workbox-expiration: 缓存大小限制和过期策略
```

### 12.4 前端内存管理

```
策略：防止长时间学习导致内存泄漏（iPad内存有限）

措施：
├── Lottie动画：播放完成后销毁实例，不保留在内存中
├── 音频缓存：使用LRU策略，最多缓存50个音频文件，超出后淘汰最旧的
├── 图片资源：使用Intersection Observer懒加载，离开视口后释放
├── React组件：使用useEffect清理函数，确保组件卸载时释放资源
├── XState服务：会话结束后停止并清理状态机服务
└── 定期检查：每10分钟检查内存使用量，超过阈值时主动GC
```

## 十三、CI/CD 流程设计

### 13.1 GitHub Actions 流水线

```yaml
# .github/workflows/deploy.yml
name: CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  # 1. 代码检查
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v2
      - run: pnpm install
      - run: pnpm lint
      - run: pnpm type-check

  # 2. 单元测试
  test:
    runs-on: ubuntu-latest
    needs: lint
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v2
      - run: pnpm install
      - run: pnpm test -- --coverage
      - uses: codecov/codecov-action@v3

  # 3. 构建
  build:
    runs-on: ubuntu-latest
    needs: test
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v2
      - run: pnpm install
      - run: pnpm build
      - uses: actions/upload-artifact@v4
        with:
          name: build-output
          path: .next/

  # 4. 部署（仅main分支）
  deploy:
    runs-on: ubuntu-latest
    needs: build
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      - name: Deploy to server
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: root
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            cd /opt/littlestar
            git pull origin main
            docker compose build
            docker compose up -d
            docker compose exec littlestar pnpm db:migrate
```

## 十五、安全设计

### 14.1 内容安全

```
三道防线：

第一道：Multi-Agent审核管线（预生成内容）
├── 4个审核Agent + 终审仲裁
├── 最多3轮迭代
└── 审核通过才入库

第二道：安全规则引擎（实时对话）
├── 敏感词黑名单过滤
├── 输出格式强制约束
├── 长度限制（防注入）
└── 语义安全检查（简单规则）

第三道：内容白名单（兜底）
├── 预审核的内容库优先使用
├── 只在库中无匹配时才用LLM生成
└── 新生成内容自动进入审核队列
```

### 14.2 数据安全

```
- 学习数据仅存本地IndexedDB
- 云端备份使用AES-256-GCM加密（详见9.2节加密方案）
  ├── 算法：AES-256-GCM
  ├── IV：每次随机12字节
  ├── 密钥派生：PBKDF2 + SHA-256 + 100000迭代
  └── 认证：GCM 128位认证标签防篡改
- 不收集个人隐私信息（无实名、无位置、无照片）
- API Key仅存服务端环境变量，不暴露给前端
- HTTPS强制（Let's Encrypt + 自动续期）
- 所有API接口JWT鉴权 + Rate Limiting（详见10.2节）
- 前端敏感数据（如Token）存储在httpOnly cookie中
```

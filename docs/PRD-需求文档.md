## 一、产品愿景与定位

### 1.1 产品愿景

打造一款面向4-5岁幼儿的**家庭英语启蒙辅助工具**，通过 AI 驱动的个性化教学引擎，结合**掌握学习法（Mastery Learning）**和**自适应学习（Adaptive Learning）**理论，以"亲子共学"为核心模式，让每个孩子在家长陪伴下按照自己的节奏快乐学习英语。

> ⚠️ **产品定位明确**：本产品定位为**家庭英语启蒙辅助工具**，不是线上培训/教育服务，不替代幼儿园教学和人际互动。产品辅助家长在家庭场景中为孩子营造英语启蒙环境。

### 1.2 产品命名：LittleStar（小星辰）

寓意每个孩子都是一颗独特的小星辰，在知识的宇宙中闪耀自己的光芒。星星也是产品激励系统的核心元素。

### 1.3 差异化定位

| 维度 | 传统竞品（斑马AI课/叽里呱啦等） | LittleStar |
|------|------|------|
| 教学模式 | 录播课+简单练习 | AI驱动自适应+掌握学习法 |
| 个性化程度 | 统一进度 | 真正个性化学习路径 |
| 内容安全 | 人工审核 | Multi-Agent自动审核管线 |
| 学科扩展性 | 绑定单一学科 | 通用引擎+可插拔学科包 |
| 商业模式 | 年课/季课付费 | 工具订阅制（详见商业模式章节） |
| 核心理念 | 教培导向 | 家庭辅助工具+亲子共学 |

### 1.4 竞品分析

| 竞品 | 优势 | 劣势 | 我们的机会 |
|------|------|------|---------|
| 斑马AI课 | 品牌强、内容丰富、体系成熟 | 录播为主，个性化弱；双减后受限 | AI自适应个性化 |
| 叽里呱啦 | 互动性好、启蒙阶段体验佳 | 内容更新慢、高阶内容少 | 通用引擎持续生成内容 |
| 多邻国（Kids） | 游戏化强、国际化 | 不够本地化、幼教专业性一般 | 本土化+幼教理论 |
| ABCmouse | 内容体量大、沉浸式 | 界面复杂、偏大龄 | 极简交互、精准适龄 |

### 1.5 政策合规

| 合规要求 | 应对策略 |
|---------|---------|
| 双减政策（学龄前线上培训限制） | 产品定位为"家庭辅助工具"而非"培训服务"，不提供直播授课、不设班级、不设老师，仅提供家长自主使用的AI辅助学习工具 |
| 《未成年人保护法》 | 无广告、无社交、无应用内购、无个人信息收集、家长管控模式 |
| 《3-6岁儿童学习与发展指南》 | 教学内容符合教育部指南中的语言发展目标 |
| 数据安全 | 学习数据本地存储为主，云备份加密，不收集实名信息 |

> **Plan B**：如国内政策仍有风险，可优先面向海外华人家庭市场（东南亚/北美），规避国内监管。

## 三、核心需求

### 3.1 教育方法论需求

#### N1：掌握学习法（Mastery Learning）— P0 必须

- 每个知识模块设定**75%掌握率阈值**（软门控）
- 采用**累计表现评估**，综合最近多次练习表现，而非单次小测验判定
- 每次评估使用 **6-8 道题目**，确保统计精度（题目来自已审核题库）
- **软门控机制**：未达标的模块标记为"需复习🌙"，但**允许孩子继续探索新内容**
  - 后台持续追踪未达标模块，自动在后续学习中穿插复习
  - 避免4-5岁孩子因被"卡住"而产生厌学和挫败感
- 超过3轮补救仍未达标的知识点标记为"需关注"，后续重点复习
- 补救教学循环最多3轮，每轮换不同教学方式

#### N2：自适应学习（Adaptive Learning）— P0 必须

- **入学自适应测评**：首次使用时通过**自适应测评算法**确定起点
  - 初始测评10-15题，根据答题表现动态调整题目难度
  - 答对则出更难的题，答错则出更简单的题（类似CAT计算机自适应测试）
  - 最终精准定位孩子当前水平，而非固定5-10题粗略评估
- **实时调整**：根据孩子的答题表现、速度、错误模式动态调整教学节奏
- **个性化路径**：不同孩子走不同的学习路径
- **弱点诊断**：AI 分析错误模式，精准定位薄弱环节

#### N3：通用教学引擎 — P0 必须

- 教学引擎是**学科无关**的，支持多学科复用同一套流程
- 新增学科只需添加**学科数据包（SubjectPack）**，无需修改引擎代码
- 首发学科：**英语**
- 后续扩展：数学、科学、语文等

### 3.2 教学内容需求

#### N4：英语学科（首发）— P0 必须

> ⚠️ **教学顺序遵循语言习得规律**：先听说（儿歌/对话/TPR）→ 后认读（字母/拼读），符合Krashen输入假说和幼儿第二语言习得研究。

学习内容范围（按语言习得规律分阶推进）：

| 阶段 | 模块 | 内容 | 预估课时 | 说明 |
|------|------|------|---------|------|
| 🥇 阶段一（听说启蒙） | 儿歌磨耳朵 | 经典英文儿歌20首，配合TPR全身反应法 | 20课时 | 先建立语感和兴趣 |
| 🥇 阶段一 | 日常对话 | 打招呼、颜色、数字、家庭成员等场景对话 | 20-30课时 | 在语境中自然习得 |
| 🥈 阶段二（认读启蒙） | 字母认读 | 26个英文字母的认读与描红 | 26-52课时 | 先听说建立基础后再认读 |
| 🥈 阶段二 | 自然拼读 | Phonics 入门（字母发音、简单CVC拼读） | 30-50课时 | 与字母认读交织进行 |
| 🥉 阶段三（阅读过渡） | 高频词 | Sight Words **30-50个**（Dolch Pre-Primer List精选） | 30-50课时 | 在绘本/故事语境中学习 |
| 🥉 阶段三 | 绘本故事 | 英文绘本故事听读 | 持续穿插 | 综合运用 |

> **Phase 1 MVP 范围**：阶段一（儿歌5首+对话5个场景）+ 阶段二（字母A-H，8个字母的完整学习循环），用最小范围验证产品闭环。

**关于高频词目标调整说明**：  
美国母语小学生一年级目标约100个Sight Words，4-5岁非母语孩子在1年内掌握30-50个已是合理目标。所有高频词必须在故事/对话语境中学习，不做孤立单词记忆。

#### N5：内容安全保障（Multi-Agent审核）— P0 必须

- 所有 AI 生成的教学内容必须经过 **Multi-Agent 对抗审核管线**
- **6个审核角色**：课程设计师（生成者）+ 4个并行审核Agent（学科专家/幼教专家/测评专家/安全审核）+ 终审仲裁
- 4个审核Agent并行独立审核，终审仲裁汇总裁定，最多3轮迭代
- 3轮未过才标记需人工审核
- 审核力度分级：
  - **重度审核**：知识图谱、题库、教学大纲
  - **轻度校验**：课堂教学内容
  - **不审核**：实时互动对话（有安全兜底规则）

### 3.3 交互体验需求

#### N6：多模态教学交互 — P0 必须

- **视觉**：图片、动画、视频为主要教学载体
- **听觉**：AI 温柔女声老师全程语音引导，减少文字依赖
- **触觉**：点击选择、拖拽匹配、手指描红等触屏交互
- **口语**：孩子跟读/语音回答，系统识别并评分
  - **录音交互**：点击按钮开始 → 自动录制3-5秒 → 自动停止（配合麦克风动画引导）
  - ⚠️ 不使用"按住说话"模式（4岁孩子无法理解和执行持续按压操作）
- **身体动觉**：引入 **TPR全身反应法**（Total Physical Response），配合指令做动作
  - 如："Stand up! Jump! Touch your nose!" 等结合肢体动作的教学

#### N6.1：亲子互动环节 — P0 必须

- Phase 1 定位为"亲子共学"模式，每次学习中穿插亲子互动环节
- 设计"亲子小任务"：如"和爸爸妈妈一起唱这首歌""找找家里有什么以A开头的东西"
- 学习结束时提供"线下延伸建议"：告诉家长如何在日常生活中配合巩固今天学的内容
- 家长指导卡片：简要说明每个知识点的家庭练习方法

#### N7：虚拟AI老师 — P1 重要

- 设计一个友好的虚拟 AI 老师形象
- 温柔女声（类似幼儿园老师）
- 鼓励式教学风格，永远正面引导
- 后续可升级为数字人形象

#### N8：激励系统 — P0 必须

> ⚠️ **设计原则**：以内在动机为核心，外部激励为辅助。遵循自我决定理论（SDT），强调自主感、胜任感和归属感。

- **即时庆祝动画**：答对时有欢快动画+音效（核心激励，不可缺少）
- **星星**：完成模块获得星星，用图形化方式展示（如星星亮度/填满效果）
- **进度可视化**：星球地图上已解锁的星球发光，面向孩子只用图形化展示
  - ⚠️ **掌握率百分比不展示给孩子**（4岁不理解百分比），百分比数据仅在家长模式显示
- **等级系统**：简化为4级（小火苗→小星星→超级星→星辰守护者）
- ~~**连续打卡奖励**~~：**已移除**（4岁孩子没有"连续天数"的时间概念，强制打卡反而增加家长焦虑）
- **金币系统**：简化，累积星星自动转换，Phase 1 暂不设消费出口

> 💡 **内在动机优先**：鼓励探索好奇心、自主选择学习内容、强调"你学会了新东西！"而非"你得了多少分"

### 3.4 技术需求

#### N9：语音能力 — P0 必须

- **TTS（文字转语音）**：温柔女声，支持中英双语，发音标准
- **ASR（语音识别）**：识别4-5岁孩子的英语发音，给出评分和纠音建议 — **P0 必须**
  - 跟读是英语启蒙的核心环节，无ASR的MVP价值大幅降低
  - 容忍度要适当放宽（幼儿发音不标准是正常的）
  - 需服务端降级方案（Web Speech API在iPad Safari不稳定，需Whisper API作为备选）

#### N10：数据持久化 — P0 必须

- **本地存储为主**：IndexedDB/Dexie 存储学习档案、课程进度
- **云端备份**：防止数据丢失，支持恢复
- 先单用户，架构预留多用户扩展能力

#### N11：LLM 集成 — P0 必须

- 支持多 LLM 供应商切换（DeepSeek、Gemini、OpenAI 等）
- 统一 LLM 接口层，不绑定特定供应商
- **API Key 来源**：平台统一提供，用户无需自行配置
  - 成本由订阅费覆盖（详见商业模式章节）
  - 通过服务端代理调用，Key 不暴露给前端
- 规则引擎 + LLM 混合架构，LLM 仅用于4个场景：
  1. 弱点诊断
  2. 补救策略生成
  3. 实时互动对话
  4. 课程内容生成

## 四、学习流程

### 4.1 完整学习旅程

```
首次使用                    日常学习循环                      定期回顾
┌──────────┐    ┌──────────────────────────┐    ┌──────────────┐
│ 入学测评  │───▶│  教 → 练 → 评 → (补救)  │───▶│ 定期回顾测试  │
│ 确定起点  │    │  ↑                ↓      │    │ 调整教学大纲  │
└──────────┘    │  └──── 未达标 ────┘      │    └──────────────┘
                │  ↓ 达标                    │
                │  进入下一模块               │
                └──────────────────────────┘
```

### 4.2 单次学习会话（20-30分钟）

```
开始学习
  │
  ├── 热身环节（2-3分钟）
  │    └── 儿歌/TPR动一动（唤醒注意力+英语语感浸润）
  │
  ├── 模块1（约10分钟）
  │    ├── 教学环节（3-5分钟）：动画+AI讲解+示范
  │    ├── 练习环节（3-5分钟）：互动练习+语音跟读
  │    └── 评估环节（2-3分钟）：小测验（6-8题）判断掌握率
  │         ├── ≥75% → 获得星星 → 模块2
  │         └── <75% → 标记"需复习🌙" → 仍可继续模块2（软门控）
  │              └── 补救教学穿插在后续学习中
  │
  ├── 模块2（约10分钟）
  │    └── 同上结构
  │
  ├── [可选] 亲子小任务（2-3分钟）
  │    └── "和爸爸妈妈一起xxx！"
  │
  └── 学习总结
       ├── 今日收获（获得的星星，用图形展示）
       ├── 进度可视化（星球地图更新）
       ├── 鼓励语 + 明天预告
       └── 家长提示：今日学习延伸建议
```

### 4.3 补救教学循环

```
评估未达标（<75%）→ 标记"需复习🌙"
  │
  ├── 允许继续学习新内容（软门控，不阻塞）
  │
  ├── 在后续学习中自动穿插补救：
  │    ├── 第1轮补救：换教学方式（如：动画→游戏→儿歌）
  │    │    └── 重新评估 → 达标？ → 是 → 标记"已掌握⭐"
  │    │                        → 否 ↓
  │    ├── 第2轮补救：降低难度 + 分解知识点
  │    │    └── 重新评估 → 达标？ → 是 → 标记"已掌握⭐"
  │    │                        → 否 ↓
  │    ├── 第3轮补救：最基础方式教授
  │    │    └── 重新评估 → 达标？ → 是 → 标记"已掌握⭐"
  │    │                        → 否 ↓
  │    └── 标记"需关注" → 记录到学习档案 → 后续持续追踪
  │
  └── 补救穿插策略：每次学习开始时，自动安排1-2个"需复习"内容的简短练习
```

## 五、Multi-Agent 审核管线

### 5.1 审核角色（共6个）

| 角色 | 职责 | 审核重点 |
|------|------|---------|
| 课程设计师 | 生成教学内容 | —（生成者，不参与审核） |
| 学科专家 | 知识正确性审核 | 英语知识点是否准确、拼写语法 |
| 幼教专家 | 年龄适配性审核 | 是否适合4-5岁认知水平、难度梯度 |
| 测评专家 | 题目质量审核 | 独立解题验证答案、选项质量、难度匹配 |
| 安全审核 | 内容安全审核 | 是否有不适宜儿童的内容 |
| 终审仲裁 | 汇总裁定 | 综合各审核意见，最终裁定 |

### 5.2 审核流程

```
课程设计师生成内容
        │
        ▼
┌───────────────────────────────────────────┐
│     4个审核Agent并行独立审核               │
│  学科专家 │ 幼教专家 │ 测评专家 │ 安全审核  │
└───────────────────────────────────────────┘
        │ 各自出具审核意见
        ▼
    终审仲裁汇总（第6个Agent）
        │
    ┌───┴───┐
    │       │
  全部通过   有异议
    │       │
    ▼       ▼
  入库使用   返回课程设计师修改
            （最多3轮迭代）
            │
            3轮未过 → 标记需人工审核
```

### 5.3 审核力度分级

| 内容类型 | 审核力度 | 说明 |
|---------|---------|------|
| 知识图谱 | 🔴 重度 | 全部6个Agent参与，必须全票通过 |
| 题库 | 🔴 重度 | 测评专家必须独立解题验证 |
| 教学大纲 | 🔴 重度 | 幼教专家重点审核难度梯度 |
| 课堂教学内容 | 🟡 轻度 | 学科专家+安全审核即可 |
| 实时互动对话 | 🟢 不审核 | 依赖安全兜底规则（敏感词过滤等） |

## 六、数据模型

### 6.1 学科数据包（SubjectPack）

```
SubjectPack（学科包）
├── id: string                    // 学科唯一标识
├── name: string                  // 学科名称（如"英语"）
├── version: string               // 数据包版本
├── knowledgeGraph                // 知识图谱
│   └── KnowledgeNode[]           // 知识节点数组
│       ├── id: string
│       ├── name: string          // 如"字母A认读"
│       ├── prerequisites: string[] // 前置知识点
│       ├── objectives: string[]  // 学习目标
│       ├── keyConcepts: string[] // 核心概念
│       ├── masteryThreshold: 0.75
│       ├── teachingMethods: TeachingMethod[]  // 多种教学方式
│       └── assessments: Assessment[]          // 评估题目（每节点6-8题）
├── placementTests               // 入学自适应测评题库
├── reviewSchedule               // 艾宾浩斯复习计划（详见下方）
└── metadata                     // 元信息
```

#### 艾宾浩斯复习计划（ReviewSchedule）

```
ReviewSchedule（复习计划）
├── intervals: number[]          // 复习间隔序列：[1, 2, 4, 7, 15, 30] (天)
├── reviewRatio: number          // 每次学习中复习内容占比：0.2-0.3（20%-30%）
├── reviewFormats                // 复习形式
│   ├── quickRecall              // 快速回忆（简短闪卡）
│   ├── contextPractice          // 语境练习（在新场景中运用旧知识）
│   └── spokenReview             // 口语复述
├── priorityRules                // 优先级规则
│   ├── dueSoonFirst             // 即将到期的优先复习
│   ├── lowMasteryFirst          // 低掌握率的优先
│   └── errorPronePriority       // 易错点加权
└── decayModel                   // 记忆衰减模型
    ├── baseHalfLife: 24         // 基础半衰期（小时）
    ├── strengthBonus: 1.5       // 每次成功复习加成系数
    └── difficultyFactor: number // 知识点难度因子
```

### 6.2 学习者档案（LearnerProfile）

```
LearnerProfile（学习档案）
├── id: string
├── name: string
├── age: number
├── masteryMap                   // 各知识点掌握率
│   └── { nodeId: { score: number, attempts: number, lastDate: Date } }
├── currentModule               // 当前学习模块
├── learningPath                // 个性化学习路径
├── weakPoints                  // 薄弱知识点
├── stats                       // 学习统计
│   ├── totalStars: number
│   ├── totalCoins: number
│   ├── level: number
│   └── totalMinutes: number
└── history                     // 学习历史记录
```

## 七、非功能需求

### 7.1 性能

| 指标 | 要求 |
|------|------|
| 页面加载 | < 3秒（首屏） |
| 交互响应 | < 500ms（点击/拖拽反馈） |
| TTS延迟 | < 1秒（语音播放） |
| ASR响应 | < 2秒（语音识别结果） |
| LLM响应 | < 5秒（内容生成） |

### 7.2 可用性

- 支持 iPad/平板横屏使用
- 触控友好：按钮/可点击区域最小 88×88pt（Apple HIG 44pt的2倍，适配幼儿操作）
- 色彩鲜艳但不刺眼，符合幼儿视觉偏好
- 全程语音引导，减少文字依赖
- 操作简单直观，4-5岁孩子能理解

### 7.3 安全性

- 无广告、无外链、无社交功能
- 内容过滤：Multi-Agent审核 + 敏感词兜底
- 数据隐私：学习数据仅本地存储+加密云备份
- 无应用内购买

### 7.4 可扩展性

- 架构预留多用户扩展能力
- 学科包可插拔，新增学科无需改引擎代码
- LLM 供应商可切换
- TTS/ASR 服务可替换

## 八、实施优先级

### Phase 1：核心引擎 + 英语MVP（P0）— 预计10-12周

- 通用教学引擎（入学自适应测评→教学循环→评估→软门控补救）
- 英语学科数据包：
  - **阶段一**：儿歌5首+日常对话5个场景（先听说）

- 基础 UI（iPad适配，去掉底部导航栏，主页卡片入口）
- TTS 语音（AI老师）
- **ASR 语音识别 + 跟读评分**（核心能力，提前到P0）
- 本地数据存储
- 简化版激励系统（星星+即时庆祝动画+图形化进度）
- 亲子互动环节（亲子小任务+线下延伸建议）
- 艾宾浩斯复习机制

### Phase 2：完整英语 + 增强功能（P1）

- 扩展字母到完整26个 (Phase 1b: I-Z)

- 虚拟AI老师形象
- 云端数据备份
- 定期回顾测试 + 大纲动态调整
- 家长端功能（学习报告+学习概览+家长锁）

### Phase 3：多学科扩展 + 原生封装（P2）

- 第二学科上线（数学）
- 验证通用引擎的学科无关性
- 学习报告增强（每周/每月趋势分析）
- 考虑 React Native / Capacitor 封装为原生App（解决PWA推送限制）

### Phase 4：高级功能（P3）

- 数字人老师
- 更丰富的游戏化元素
- 多用户支持
- 更多学科扩展

## 十、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| LLM 幻觉导致教学内容错误 | 高 | Multi-Agent审核管线 + 知识库预置 |
| 4-5岁孩子语音识别准确率低 | 中 | 放宽容忍度 + 只评估关键音素 |
| TTS声音不够自然/亲切 | 中 | 多供应商对比 + 用户可调节 |
| 孩子注意力难以持续 | 中 | 单模块控制在10分钟内 + 游戏化 |
| 教学效果难以量化 | 中 | 掌握率追踪 + 定期回顾测试验证 |
| 多学科扩展时引擎不够通用 | 中 | 第二学科上线时验证并重构 |
| 政策合规风险（双减） | 中 | 定位为"辅助工具"规避；备选出海方案 |
| PWA推送限制影响留存 | 中 | Phase 3 考虑原生封装 |
| iPad Safari兼容性 | 中 | TTS/ASR需服务端降级方案 |

## 附录

### A. 术语表

| 术语 | 定义 |
|------|------|
| Mastery Learning（掌握学习法） | 学生必须达到预定掌握水平才能进入下一学习单元 |
| Adaptive Learning（自适应学习） | 根据学生表现实时调整教学内容和路径 |
| SubjectPack（学科数据包） | 某一学科的完整知识图谱、题库、教学方法集合 |
| KnowledgeNode（知识节点） | 知识图谱中的最小学习单元 |
| Mastery Rate（掌握率） | 学生对某知识点的掌握程度百分比 |
| Remediation（补救教学） | 学生未达标时的重新教学过程 |
| Placement Test（入学测评） | 确定学生起始水平的初始测试 |
| Phonics（自然拼读） | 字母与发音对应规律的教学方法 |
| Sight Words（高频词） | 需要直接记忆的常用英文词汇 |
